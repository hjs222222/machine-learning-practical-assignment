## 旧项目警戒复盘

以下结论仅来自对旧目录的只读核查，用于避免重复问题，不作为本次实验的结果或实现来源。

1. **h=1 精度未达到目标。**旧项目的 `formal_20261105_v4_reference/metrics.csv` 中，最高的直接策略 h=1 测试 R² 为 RF 的 0.5217，目标字段 `target_R2_0_8_met` 为 `False`；因此不能把“调过很多轮”误认为达到用户希望的约 0.8。
2. **实验版本不是一个统一可重跑的结果。**旧 README 明确写出“直接策略保留第二轮冻结结果，多输出采用第三轮冻结结果”。直接与多输出来自不同轮次，不能作为一次一致的 40 模型实验来解释或比较。
3. **测试年已被反复查看。**旧协议把 2004 标记为“回溯评估，非独立盲测”。这不违背教师“前四年训练、第五年测试”的切分要求，但若再以 2004 分数选择特征或参数，就会使结果的可信度继续下降。
4. **旧主入口不是纯净从零运行。**README 说明会自动加载已有模型再继续训练；原配置还会从多个候选路径查找数据。两者都会使同一命令因历史产物或环境不同而产生不同结果，无法作为本次“从头开始”的依据。
5. **旧实现曾出现时序泄漏风险。**其调试记录承认早期版本曾用全量 2000--2004 年数据拟合归一化与特征选择，曾使用不适合时间序列的默认交叉验证或深度学习随机打乱。后续文件声称已修正，但新项目不采纳任何旧结果，必须从第一版就用自动测试证明边界。
6. **代码和证据链碎片化。**旧 `code/` 中并列存在 `experiment.py` 至 `experiment_v6.py` 与多组 `acceptance3_v2/v3/v4` 入口，报告又依赖冻结轮次；验收时难以回答“当前表格由哪一次完整运行产生”。

本项目的防线：固定唯一数据路径；每次正式运行新建带时间戳且含配置哈希的目录；默认不加载历史权重；配置选择只读训练期开发指标；同一正式运行一次性产出直接、多输出、两种集成及全部指标；报告只引用该运行目录的产物。

数据有 1,827 条逐日记录，时间为 2000-01-01 至 2004-12-31，包含 `Date`、`Discharge` 和七个气象字段；`Swe` 是常量列。训练集固定为 2000--2003 年，测试集固定为 2004 年。所有特征构造、缩放参数、特征选择和调参只能在训练期内拟合；测试集只允许一次最终评价。

## 模型与评价设计

- 预测目标：未来 1--7 天的 `Discharge`。
- 预测策略：每种基模型均实现 7 个直接模型和 1 个原生多输出模型；禁止 `MultiOutputRegressor`。
- 基模型：MLP（人工神经网络）、RandomForestRegressor（随机森林）和原生 PyTorch LSTM。
- 集成：三种基模型预测的简单平均，以及仅由训练期滚动 OOF 预测训练的 Ridge Stacking；禁止把测试集预测或真实值用于元学习器拟合。
- 调参：`TimeSeriesSplit` 网格搜索。随机森林与 MLP 使用 sklearn 管线；LSTM 使用同一时间切分的显式候选参数循环。
- 指标：每个策略、每个模型、每个预测步输出测试集 R²、RMSE、MAE。R² 是用户关注的“精度”主指标。
- 合法性能目标：优先提升 h=1 测试 R²，并记录训练期验证分数；只有验证改进且无数据泄漏的配置可以进入最终测试。h=2--h=7 的指标允许随预见期下降。不得承诺或人为制造 h=1 R²≈0.8。

预测原点定义为 t：允许使用在 t 当日已经观测到的 `Discharge(t)`、气象字段及其历史值，禁止使用 t+1 及之后的任何字段。为使 h=1--h=7、直接/多输出指标可横向比较，正式测试统一使用 2004-01-01 至 2004-12-24 的 359 个预测原点，保证每行的 t+1--t+7 标签均在 2004 年内。训练期时序验证须有 7 天 gap，防止训练标签越入验证期。

正式测试只能在参数冻结后运行一次。若 h=1 R²低于约 0.8，保留真实结果、训练期开发分数及误差分析；不得重新开放测试集调参。三份阶段验收 Markdown 在该同一冻结运行后按任务筛出证据，因此数值有同一来源。

## 特征设计

对数据执行：字段中文说明、全列可视化、季节和月份编码、仅使用预测时点可得的过去/当日值构造滞后与滚动统计、训练集 Z-score 标准化、训练集互信息选择。不能使用未来日期的径流或气象数据，也不能使用测试期统计量。

为确保模型输入可解释，保留特征字典：每个特征记录来源字段、时间偏移、统计窗口和是否被选中。特征集合及其数量由训练期内的时序交叉验证确定，写入结果文件。

## 验收与报告设计

三次验收各自生成一份 Markdown 记录，放入 `验收/acceptance 1`、`acceptance 2`、`acceptance 3`。每份报告只链接其自身目录内的最终 CSV、图片和代码副本；标题按规则以“任务x+内容”命名。Markdown 使阶段过程可持续补充，最终报告使用 Word。

最终 Word 报告从教师 `.doc` 模板转换为可编辑 `.docx` 后填写。封面中的题目、专业、学号、姓名、指导教师、成绩和“三人详细分工”不臆造，保留明确的待填写标记。正文严格覆盖模板六章和代码提交说明，并用实际生成的图表、指标、调试记录替换占位文字。

根据用户转述的教师最新要求，最终 Word 不粘贴源码。模板的“附录”改为“代码提交说明”，给出代码压缩包文件名、唯一运行入口、依赖清单和数据 SHA-256。最终代码包包含 `code/`、`tests/`、`requirements.txt`、运行说明和配置/数据哈希清单；不包含教师原始数据、权重、缓存、旧项目内容或大体积中间输出。

## 运行资源和版本

本机已核验可用 PyTorch CUDA（RTX 4060 Laptop GPU）、24 个逻辑 CPU 核和充足 D 盘空间。先进行不读取测试集的短计时试跑，再把模型候选、交叉验证折数、随机种子和时间预算冻结进配置；LSTM 耗时超预算时只缩小其训练期候选网格，不减少教师要求的模型数量。项目将使用仅本地 Git 版本记录，不推送，不提交原始数据副本、权重、缓存或敏感文件。
