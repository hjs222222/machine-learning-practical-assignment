本课题根据流域逐日径流和气象观测，预测未来1—7天的径流，属于监督学习中的时间序列多步回归任务。输入为预测原点t当天已观测值及其历史，输出为t+1至t+7的流量。

实验依次完成数据分析、因果特征工程、人工神经网络/随机森林/LSTM建模、简单平均与Stacking集成。三种基模型各构建七个直接模型与一个七输出模型，共24个；两类集成共16个。全程只使用教师CSV。

正式回溯测试的最高h=1 R²为0.5103（multi/RF），RMSE为589.20，MAE为194.99。本次未达到约0.8目标。所有结果以原始流量尺度报告，不将相关系数平方替代R²。





训练数据为2000—2003年。为保证七步标签全部留在训练期，训练预测原点最晚到2003-12-24。正式测试预测原点为2004-01-01至2004-12-24，共359行。每行标签为未来1—7天，同一原点同时用于所有策略。2004年内较早日期的已观测径流可作为随后原点的输入，这是滚动预报，不是用测试标签拟合模型。

开发采用两折TimeSeriesSplit，gap=7。Stacking采用三折外层OOF，每个外层训练段再独立两折网格搜索[5]。训练标签最晚日期必须早于验证起点。每次fit重新计算互信息、缩放和模型参数；验证与测试不参与这些统计。

方法依据与适用范围

随机森林通过多棵树的集成降低单棵树的方差[2]，适合作为本实验的非线性回归基线；人工神经网络通过反向传播学习非线性关系[7]，但在四年日样本上需要控制网络容量和训练预算。LSTM以门控状态处理历史序列[3]，本实验只让它读取起报日及此前的观测，不把未来气象当成已知输入。Stacking以基模型的折外预测构造第二层输入[4]，因此元学习器的拟合样本不能与基模型的拟合样本混同。三种个体方法和两种集成均采用同一测试日期与原始流量尺度，比较才有意义。

直接策略分别拟合h=1至7七个单输出模型，允许不同预见期选择不同参数；多输出策略一次拟合七列目标，利用目标间共享结构。两者各有七个最终预见期结果，但模型计数不同：每类个体模型为七个直接模型加一个多输出模型。简单平均与Stacking也遵循相同的八模型计数。递归策略需要把前一步预测再次送入下一步，误差会逐步传播，且并非本次指导书要求，故不列入正式比较。

整条实验流程采用同一预测原点定义。先用教师CSV建立按日排序的原始表，再从每个起报日向前取历史窗口，形成输入X及七列未来标签y。开发阶段只在训练年份内部划分时间折，网格搜索给出每个模型的超参数；选择完成后，正式模型在允许的全部训练行上重新拟合。最后保存每个起报日、目标日期、真实值和预测值，再由逐日文件计算指标。这样既能逐条追查某个洪峰日为什么产生大误差，也能避免只保留一张汇总表而无法核对指标分母。所有模型共享同一组359个测试起报日，比较模型时不因缺失日期改变样本组成。

特征构造与训练折内处理

构建月份正余弦与四季one-hot，冬季为12—2月。非恒定字段构建滞后0/1/2/3/7/14/30天；径流、降水、最高/最低气温构建3/7/14天滚动均值、标准差、最大值，窗口截止t。总计91列候选输入。14天LSTM样本仅由历史序列组成；候选可使用最后7天或14天。

月份不是普通大小顺序：12月与1月在季节上相邻，直接使用整数1至12会把两者放到数轴两端。因此月份用正弦和余弦表达周期，四季用独热编码表达离散类别。滞后0表示起报日当天已观测值，滞后1表示前一日；滚动窗口的右端固定在t，绝不使用t+1及以后的真实量。特征名称和日期索引同时检查，避免仅凭数组形状正确就误把未来标签移入输入。

常见缩放包括Min-Max、Z-score、鲁棒缩放；本次使用Z-score。常见选择法包括过滤、包装、嵌入；本次以逐目标互信息的平均值排序，选择16或24列。全部拟合限于本折训练行；正式模型以全部训练期拟合后只transform测试输入。

Min-Max把训练值映射到固定区间，便于比较量纲，却容易受训练期极值影响；Z-score按训练均值和标准差中心化，在本实验中作为统一数值输入；鲁棒缩放用分位数降低极端值对参数估计的影响。三者都只应在训练折拟合参数，验证折和2004数据只应用已拟合参数。互信息属于过滤式选择，先给候选输入与目标的依赖打分，再在训练折内按所需数量截取；本实验对七个输出分别评分并取平均排名，形成多输出共用特征，而不是在测试年重新选列。

网格搜索和目标变换

训练期先导搜索显示h=1验证R²约0.67—0.69，随后加入相对当天已知径流的残差候选。目标候选为原始值、平方根和log1p；残差方案在相应目标尺度预测相对Q(t)的变化，再逆变换恢复流量。最终模型均由冻结网格决定，测试结果不反向影响选择。

ANN为单隐层MLP；RF使用120棵树并搜索叶节点最小样本数；LSTM为单层循环网络、线性输出头和Adam优化器。七输出网络不是七个独立包装器。LSTM以purged CV选择30或70轮训练，不采用随机验证集早停。



正式预测与集成结果

R²=1−Σ(y−ŷ)²/Σ(y−ȳ)²；RMSE为均方误差平方根，MAE为绝对误差均值。R²允许为负数，不截断也不将其改为相关系数平方。所有预测通过相同非负约束处理，指标保持原始尺度。

R²的分母使用本次同一预见期359个真实值相对其均值的总平方差，因此不同预见期要分别计算，不能把七天预测先拼接后冒充逐日结果。水文领域常用的Nash–Sutcliffe效率与此形式一致[6]。RMSE会更重地惩罚少数大误差，MAE反映平均绝对偏差；当洪峰稀少且幅值高时，三个指标可能给出不同的模型排序。报告同时列出持续性基线，即用起报日实测流量预测未来各日，以确认复杂模型是否真正超过简单参照。

简单平均对三个基模型原尺度预测等权平均。Stacking仅用训练期嵌套OOF预测拟合Ridge；直接策略每h三列元特征，多输出为21列基预测到七个目标。两种集成均为实际生成结果，未退回单模型代替。

持续性基线与误差分析



正式h=1最高R²模型的20个最大误差日占其平方误差总和的91.1%。该统计只用于冻结后的解释，未用来重选模型。极端值被保留；若模型对少数洪峰误差较大，R²与RMSE会明显下降，MAE则相对不敏感。



正式结果与后续研究的边界

正式冻结结果中，h=1最高为原生七输出RF：R²=0.510331、RMSE=589.198、MAE=194.993；同日期持续性基线R²=0.398849。直接ANN的h=1 R²为0.494210，不能仅因其MAE更低就改称为R²最优。正式结果包含三类个体模型、两种集成和两种策略的70行逐预见期指标。上述数值来自同一冻结运行，并非把不同实验中各自最好的预见期拼成一个模型。

正式运行之后，项目又进行第一天精度研究。一次固定单种子ANN回溯得到R²=0.506473；另一份加入当天降雨的固定三种子ANN回溯得到R²=0.503079，两者都在相同359个起报点上低于正式RF的0.510331。其余训练期方案，包括目标一致互信息、单输出RF和梯度提升树，保留为开发期对照，没有新的2004成绩，也未替换教师要求的40个正式模型。开发期某一年或某个种子的高分不能写成正式测试精度；2004此前已被查看，所有相关成绩均属于回溯评价而非独立盲测。

从图中的过程线可以看到，模型对平稳低流量区间的走势通常更容易跟随，而洪峰到来的时间和幅度更难同时命中。把大误差日单独列出，是为解释R²和RMSE为何受少数日期显著影响；这些日期仍完整保留在359个测试起报日中，不以“异常样本”为由删去。持续性基线在h=1已有一定分数，说明当天实测流量本身包含短期记忆；模型超过基线的幅度才是额外信息的实际贡献。随着预见期拉长，未来降水尚未发生，固定参数且只使用历史气象的模型信息会减少。因此本报告展示h=1至7的全部结果，包括负R²，不把后六天隐藏在一个均值里，也不对结果曲线施加单调约束。

日期与多步标签边界：起初的实现需求只写按年份切分，不足以证明七步标签未跨界。先写因果与日期失败测试，再实现训练标签截止日断言、gap=7和359个共同测试原点，边界测试通过。

输入/输出一致性：为ANN、RF、LSTM分别编写原生七输出、单输出列形状、训练折缩放和序列化恢复测试，确认预测矩阵与实测日期对应。残差扩展先由失败测试暴露不支持参数，再验证在零变化目标下能重构当天流量。

ANN收敛：快速单元测试故意只运行10轮，会出现ConvergenceWarning；正式训练的警告数量记录在每个搜索JSON中，不隐藏为已完全收敛。网格预算固定，未在正式测试后追加轮次。

正式96组搜索累计记录37条收敛警告（含未胜出的候选和OOF内搜索），说明有限预算下部分ANN候选未充分收敛。它们是优化预算限制，不能据此把测试分数解释为理论上限。

使用技术：pandas日期索引、numpy序列、matplotlib可视化、Pearson分析、月份正余弦/季节one-hot、滞后/滚动、互信息、Z-score、MLP、随机森林、PyTorch LSTM、GridSearchCV、purged TimeSeriesSplit、嵌套OOF、Ridge Stacking和Git版本记录。

本次全部模型最高h=1 R²为0.5103。未实现约0.8的性能目标，应将这一点作为结果限制，而不是用训练分数替代测试分数。预见期越长，可用历史对未来的解释力可能下降，但不强迫指标单调。

当前限制包括四年训练数据较少、气象只截至t、有限网格和单随机种子。后续如有新的合法独立数据，可预先设计验证期，再研究更多历史窗口、洪峰加权损失或多种子稳定性；本次不能用2004结果继续选参。由于2004已在旧实验查看，本次属于冻结配置后的回溯评价。

本实验说明，时间序列任务的日期可用性和评价协议与网络结构同样重要。应用于防洪等实际场景时，应同时检查平均误差、洪峰漏报和预报时效，不能仅依据一个R²宣布可部署。个人心得及成员协作体会待三位成员按实际参与补充。

从失败研究中得到的具体认识是：更复杂的表示并不会自动带来更高的测试分数。训练期加入当天降雨在困难年份有小幅改善，但授权回溯后仍低于正式RF；固定网格的平方根增量提升树在训练期三年都超过其原流量目标版本，困难年却仍低于既有ANN验证成绩。两项比较的因果范围不同，不能把训练期进步、回溯期进步和未来部署效果划等号。后续改进应先在新的合法独立年份预先锁定评价方案，再检验洪峰日和全年指标是否共同改善。

本项目还暴露出模型选择与性能表述之间的区别。开发期的交叉验证用于从有限候选中选配置，分数会受年份水文过程、搜索次数和随机种子影响；它不是对未见年份的承诺。2004回溯只能回答固定模型在这一历史年份的表现，不能证明同样分数会在另一流域或未来洪水中重现。实际使用前还需要确认气象与流量观测能按预测时刻及时到达，检查缺测与设备故障时如何回退，并按防洪业务对漏报洪峰的代价建立单独评价。由于这些数据和场景没有在本课程资料中提供，本报告不声称完成业务部署。真实小组分工和个人收获也应由三名成员按实际工作补写，避免把统一的技术记录误当成每个人相同的贡献。
